# תוכנית החיבור למסד הנתונים

## העיקרון

כל המסכים עובדים רק מול החוזה שמוגדר בקובץ `src/data/DataService.ts`. החוזה הזה מגדיר את כל הפעולות על הנתונים: קריאה, שמירה, עדכון ומחיקה.

כרגע הוא ממומש על ידי `LocalDataService`, שומר המידע הזמני בדפדפן. החיבור למסד הנתונים יעבוד כך:
1. כותבים מימוש חדש של אותו חוזה מול סופהבייס.
2. בוחרים בו במקום אחד בלבד: `createService` בקובץ `src/data/DataContext.tsx`.
3. המסכים עצמם לא משתנים.

## איך כללי ההרשאה יעברו למסד הנתונים

הכללים מרוכזים היום בקובץ `src/core/permissions.ts`, ונבדקים בבדיקות שבקובץ `tests/permissions.test.ts`. במסד הנתונים כל כלל ייאכף ברמת השורה, כך שכל משתמשת מקבלת מהשרת רק את השורות שמותר לה לראות:

| הכלל היום | במסד הנתונים |
|---|---|
| `can.viewClient` | לקוחה גלויה למנהלת פעילה, או ליועצת המשויכת כשהכרטיס לא בארכיון |
| `can.manageLeads` | טבלאות הלידים פתוחות למנהלות בלבד |
| `can.modifyEntry` | עריכה ומחיקה של רישום מותרות לכותבת שלו או למנהלת |
| `assignClient`, `archiveClient` | פעולות שרת שבודקות שהמבצעת מנהלת. ליועצת אין הרשאה לשנות את שדה היועצת |
| קבצים מצורפים | אחסון פרטי. גישה לקובץ רק למי שרואה את הלקוחה |
| יצירת משתמשת ואיפוס סיסמה | פונקציה בצד השרת עם מפתח ניהול שאינו נחשף לדפדפן |

## מה עוד יידרש

- **פרויקט בסופהבייס:** באזור פרנקפורט, עם הרשמה עצמית חסומה (רק מנהלת יוצרת משתמשות).
- **שירות דיוור:** לשליחת התראת מייל כשמשייכים לקוחה ליועצת. ההודעה לא תכלול פרטים רגישים.
- **העברת נתוני ההדגמה:** לא יועברו. המערכת האמיתית תתחיל ריקה.
